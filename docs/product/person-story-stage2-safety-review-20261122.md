# 人物の語り原本とBOOK接続：変更前の安全確認

対象：`codex/book-answer-shared-design` の現行コードと隔離TESTのスキーマ。2026-11-22時点。これは第2段階の実装前確認であり、確定済みの「一つの原本」を変更する提案ではない。

## 確認した実装差

| 論点 | 現行 | 接続時の危険 |
| --- | --- | --- |
| 本文 | `family_free_stories` は人物＋3枠、`answers` は作品＋質問。別々に更新する。 | コピーだけでは編集のたびに不一致が生じる。無料質問とBOOK質問の対応も固定できない。 |
| 音声・写真 | 無料は `family_free_story_media` と非公開 `family-free-media`、BOOKは `media_assets` と `audio`・`photos`。 | 行だけをリンクしてもBOOK紙面・PDF・Webブックは無料側のファイルを読めない。 |
| 鍵 | 無料は `visibility`、BOOKは `access_override`。無料の本人回答は現在 `private` で新規作成される。 | 新規は家族共有に改める必要がある。既存の鍵を一括変更してはならない。 |
| 完成 | `guard_confirmed_book_source` が収録済み `answers`・`media_assets` と保存ファイルを固定する。 | `answers` を完成後も編集可能な人物原本にすると、固定BOOKの保証と衝突する。 |
| 権限 | 無料の非公開は本人のみ。BOOK共同管理者の招待画面には権限説明があるが、本人同意の記録と別家族アカウントからの承認導線はない。 | 画面側の表示だけを広げると、本文・件数・Storage・署名URLで漏出する。無料メディアの署名URLは現状1時間有効。 |

隔離TESTには無料の語り1件（鍵付き0件）、BOOKの鍵付き回答73件がある。無料の語り1件は、現時点でBOOK作品に紐づいていない。既存顧客データの一括変更は不要であり、しない。

## 最小の安全な接続方針

1. 人物の可変原本は、既存の `family_free_stories` を拡張して保持する。質問対応は別の変更可能な対応表で管理し、現行3枠・質問文を固定キーにしない。既存の無料データはそのまま保持する。
2. 制作中の `answers` は原本を参照するBOOK用投影として扱い、BOOKからの変更は一つの保存APIで原本へ反映する。既存BOOK回答は、本人が対象の語りを開いた時に個別接続する。両方に異なる本文がある場合は自動上書き・自動統合せず、接続を止める。
3. メディアの原本参照にはバケット名と保存パスを持たせ、BOOK用のコピーや変換が必要な場合は出力用の派生物と明示する。ファイル登録完了まで回答・出力を成功扱いしない。鍵付きメディアは認証付き取得とRLSを使い、過去に発行した署名URLの残存時間も検証する。
4. BOOK完成時は既存の確認済みスナップショット・出力経路を維持する。以後、可変原本だけ編集・鍵変更でき、収録済み版へは反映しない。
5. 新規の語りだけ家族共有を初期設定とする。既存の鍵は変更しない。共同管理者の鍵付き原本アクセスには、本人が存在すれば本人による同意、存在しなければ代理制作者の明示的な確認を記録する。単なる家族管理者やお手伝いは許可しない。既存BOOK自体の権限を新しい原本接続で広げない。

## 適用・検証の順

権限・同意・メディア取得境界 → 可変原本と質問対応 → BOOK回答の読み込み・書き込み接続 → 既存BOOKからの個別接続 → 完成スナップショット回帰。各段階で別利用者のJWTによる本文・件数・パス・署名URL・実ファイルの拒否を確認する。TESTの実画面は認証メールの送信制限が解除されてから行い、既存の成功済み購入・公開E2Eは重複させない。

## 判断待ち

- 既存の鍵付きBOOK回答に本人同意の記録がない場合、既存BOOK権限を維持しつつ、新しい年輪原本への鍵付きアクセスのみ同意後にする方針を推奨。既存権限を即時停止すると制作中の作品を壊す可能性がある。
- 同一人物・同一質問で既存の無料語りとBOOK回答の内容が異なる場合は、両方を保持して接続を止め、利用者がどちらを原本にするか選べるまで自動統合しない。
