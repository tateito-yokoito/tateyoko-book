# 利用動線（正本）

状態・権限は [product-spec.md](./product-spec.md) を参照する。購入形態と制作中の役割を混同しない。同じ物語は同じ制作・完成処理に接続する。

## 無料3問から本編

`無料3問 → 回答保存・再開 → 体験完了 → 共通の商品選択 → 必要なら認証 → 共通の最終確認・サーバー見積もり → Stripe決済 → 既存の物語に購入権利を接続 → 本編開始`

購入済みの人を無料体験や基本商品の再購入案内に戻さない。無料3問終了後のコピー・保存期限・購入画面の細部は要確認。参照実装は `src/App.jsx` の `trial_experience` と `src/PurchaseSelectionEntry.jsx`。

## HPからの購入とギフト

`HPの購入入口 → 同じ商品選択 → 必要なら認証 → 同じ最終確認・見積もり → 同じ決済開始 → 購入済みの物語／受取先に接続`

ギフトAの受取人は購入済みの本編を始める。ギフトBでは購入者側が制作を管理し、本人のアカウントを必須にしない。ギフトリンクの受取人に無料3問・価格案内を再表示しない。ギフト初期権限と `recipient_led` / `family_managed` の全パターンの対応は要確認。アプリホーム内に「家族に贈る」入口は置かない。

## 物語・BOOK

`本人または制作権限者のホーム → 次の問い／問いの一覧／写真から語る → 語り・写真・音声・動画 → 語りを見る → 本に仕上げる（表紙 → 収録 → 紙面 → オプション → 注文） → 必要な追加決済を含む最終確定`

ホームと制作画面は同じ作品状態・共通部品を使い、権限によって操作と非公開情報だけを制限する。「写真から語る」は独立した入口で、9テーマではなく「写真から残した記憶」の章に収録する既存設計を維持する。本人の題名・定型問い非表示指定がBOOK/PDF/Webブックへ一致して反映されるか要確認。

`BOOK完成 → 運営確認中（本に仕上げるは閲覧専用、本棚に確認中カード） → 運営公開（本に仕上げるの表示終了、本棚でWebブックを閲覧、通知・ホーム案内）`

完成後の増刷は本棚起点の別注文という方向だが、購入入口の最終UXは未決定で新設しない。

## 季節の記憶箱

`公開後ホーム → 今季の記憶箱 → 今の想いを残す／人生をもう少し語る → 写真・文章・音声を自動保存 → 離脱・再開 → 全体確認 → この記録を終える → 記憶のかけら一覧・詳細`

新しい季節には今季の箱を上段、前季の未確定箱を猶予期間だけ下段に表示する。早期確定済みの箱は編集操作・期限案内を出さず、記憶のかけらへ導く。期限を過ぎた箱はホームから消え、内容のある記録だけ確定して残る。

公開後の基本ナビゲーションは **ホーム｜記憶のかけら｜本棚**。入力中は非表示。BOOK制作中と運営確認中は自分の記憶のかけらを出さない。他作品の管理・お手伝いと閲覧可能な家族の本棚は権限に応じて維持する。

## 運営閲覧

管理画面からは顧客と同じUI部品と役割別表示条件を使う。取得だけを閲覧専用経路にし、顧客の作品・回答・設定・進捗に影響しない。実装済み経路の全網羅は要確認。
