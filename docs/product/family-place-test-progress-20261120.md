# 家族の場所・初期実装のTEST進捗（2026-11-20）

対象ブランチ: `codex/book-answer-shared-design`。本番DB・本番配信・mainには未反映。

## 実施済み

- 認証入口は現行の`Scene_Login`を再利用。メールOTPと、環境で有効な場合のLINE OAuthを共用する。OAuth戻り先には`app=family_place`が保存される。LINEで初回セッションが復帰した場合も既存のプロフィール初期化を呼ぶ。無料入口では`ensureUserFoundation`を呼ばず、BOOK作品を自動作成しない。
- `family_free_stories`など人物単位の無料記録表と、非公開Storageバケットを隔離TESTに追加。既存BOOK・購入テーブルは変更していない。新表はRLS有効、匿名ユーザーは初期化RPCを実行できない。
- 共有受取人の`media_assets`参照を、対象回答の`private_forever`条件で絞る最小SQLを隔離TESTへ適用。既存共有作品のメディアには、回答未紐付け行がないことをTEST・本番とも集計値で確認した。本番DBは読み取りのみ。
- 現行録音部品、写真補正、回答UI、文字起こし・文章整形Edgeを再利用する無料記録用分岐を追加。Edgeの既存TEST版と候補コードが一致することを確認してから、TEST版のみ更新した。
- `VITE_FAMILY_PLACE_ENABLED`をTESTビルドにだけ設定。通常ビルドでは無料アプリのコードが生成物に含まれないことを確認した。
- `npm run test:answer-ui`は18件成功、`npx vite build`成功。年表の「登録済み事実のみ」関数をローカルで確認。
- TEST DBのロール・JWTクレームを模擬したロールバック付き結合試験で、家族と人物の初期化、人物単位の記録追加・再編集、初期化時にBOOK作品数が増えないこと、本人限定の本文が別ユーザーに見えないことを確認。試験データはロールバックした。実JWTとStorageのE2Eとは区別する。
- 新記録の`INSERT ... RETURNING`がRLSで拒否されたため、画面の保存接続を「追加→別リクエストで再取得」に修正。ポリシー内の曖昧な列参照も前進migrationで明示した。変更後の追加・再読込・再編集は上記のロールバック試験で成功。

## 未検証・残作業

- 実JWTでの共有先・無関係者・正当な共有者の本文、メディア行、件数、保存パス、署名URL、実ファイル取得。最初の架空作品は別の家族制作向けRLSが共有回答も遮るため、今回のポリシー単独の検証には使えないと判明した。この作品に付けた一時共有は`revoked`へ戻した。通常のTEST作品で共有回答と本人限定回答を分けた検証が必要。
- 無料アプリの実画面での登録、人物編集、3問の音声・文章・写真保存、再読込、再編集、メディア再生、権限境界。現時点ではE2E合格としない。
- 新しい無料3問の本文はオーナーが調整中。現在の質問文は隔離TESTの技術検証に限る暫定値であり、商品仕様として確定していない。
- TEST HTTPSへの画面配信。現時点の画面確認はローカル開発サーバーのみ。

一時的な権限検証画面も、独自の認証コード処理を撤去し、現行`Scene_Login`と同一セッションを使用する。検証後、この一時画面を削除する。
