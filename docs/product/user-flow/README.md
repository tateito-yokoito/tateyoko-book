# 利用動線マスター

## 正本

利用動線、利用者の役割、状態遷移、分岐条件、設定・同意の意思決定時点は、[`user-flow-master.xlsx`](./user-flow-master.xlsx) を正本とする。

対象は、HPの入口から無料3問、購入、本人Accountへの接続、はじまりの章、本編、仕上げ、完成後まで。

ケースの位置づけは次のとおり。

- A：本人起点
- B：家族起点
- C：Bの受取人側ビュー。独立した契約フローではなく、招待された本人から見た体験確認に使う。

## 他の正本との関係

- 商品・ブランド・UXの原則は [`../../product-brand-ux-master-v2.0.md`](../../product-brand-ux-master-v2.0.md) を優先する。
- 認証、権限、個人情報保護、DB制約、RLS、決済の技術的安全条件は、承認済みの実装仕様、migration、コードをExcelだけで上書きしない。
- Excelの「実装状態」は、記載された根拠の範囲を示す。本番反映やE2E完了を自動的に意味しない。

正本間に矛盾を発見した場合は、どれかに勝手に合わせない。`04_運営チェック` に論点、影響、確認先、次アクションを追加し、判断後に関係する正本を更新する。

## 更新方法

1. 会話やレビューで論点を整理する。
2. 決定した内容を同じ `user-flow-master.xlsx` へ反映する。
3. Account、操作者、語る人、Person、Payer、Supporter、Deviceの関係が崩れていないか確認する。
4. 設定や同意を変更した場合は、`02_設定同意` と `05_実装対応` も確認する。
5. 未確認の保存先や実装状態は推測せず、`要確認` として残す。
6. Excelと関係する正本だけを対象にコミットする。

`user-flow-master-v0.2.xlsx` のような別バージョンファイルは作らない。履歴と変更理由はGitで管理する。

## 構造の固定

2026年9月21日時点で、シート構成、主要列、Flow ID体系を一旦固定する。以後はQ01・Q02をはじめとする商品仕様の意思決定と、実装差分の更新を中心に行う。

新しい運用上の必要が確認できた場合を除き、列やシートを追加して構造を磨き続けない。構造変更が必要な場合は、先に `04_運営チェック` へ理由と影響範囲を追加する。

## 実装時の扱い

Codexや実装担当者は、利用動線を変更する前にこのExcelを確認する。既存コードと異なる場合、コードへ自動的に合わせず、仕様差分として確認する。

ただし、Excelに記載がないことを理由に認証・権限・プライバシーの既存ガードを弱めてはならない。
