# 家族アプリ共用デモアカウント

本資料にはパスワード、管理鍵、認証トークンを記録しない。対象は本番家族アプリの限定公開だけとし、既存BOOKのメール・LINEログインと一般向け登録設定は変更しない。

| 番号 | 初期状態 | 実データの条件 |
| --- | --- | --- |
| ① | 記録0件 | 専用家族は空。人物・BOOK・語りなし |
| ② | 家系図・無料3問 | 架空の本人・親・子、登録済み関係、人物に紐づく架空の無料回答3件 |
| ③ | BOOK制作中 | ②とは別の架空家族・人物、実際の `book_projects` と編集中の回答。`subject_person_id` を人物に設定 |

## 適用した変更

1. Supabase Auth管理画面で専用メールアドレス4件を作成した。パスワードは各アカウント個別にオーナーが設定・保管し、アプリ・リポジトリ・操作ログには残さない。メール確認済みの専用ユーザーとして作成し、サインアップや既存のOTP設定は変更していない。
2. その4ユーザーIDだけを既存 `family_place_early_access` に登録する。家族アプリは従来のメール・LINE認証と、家族アプリ専用のパスワード認証を併設する。許可リストの判定は既存RPCとRLSが担う。
3. ①〜④の家族を分離して架空データを投入する。③④には既存のBOOK作品・回答・確定・Webブックの仕組みを使用する。デモ作品には注文・決済・ギフト・配送・製本ジョブを作らない。デモのBOOK権利は既存の `legacy` 状態を用い、商用の購入済み注文と混同しない。公開版は架空内容のみとし、既存の完成処理を通す。完了処理が注文を要求する場合は迂回せず中止する。
4. 各IDについて家族・人物・語り・BOOKの所属と表示を検証する。別デモの人物・鍵付き記録は相互に取得できないことを別JWTで確認する。

## 2026-11-23 の確認

- ①は実ログインで人物0件の家族ホーム、②は実ログインで人物4人・家系図・無料3問を確認した。

- DBの認証済みロールで①〜④を個別に照会し、それぞれ自分の家族だけが表示された。③から④のBOOK回答は0件。②から非公開メディア行と対象Storageオブジェクトは0件。これはロールを切り替えた検証であり、各アカウントの実JWTを用いたメディア取得試験ではない。

## 初期状態への復元

復元時は先にデモ利用を停止し、4件のセッションを失効させて同時編集を止める。許可リストを外すだけでは既存JWTからDBへのアクセスを止めきれないため、これだけを排他手段にしない。上表の家族ID・BOOK作品IDが一致することを確認し、対象家族だけをバックアップする。人物・関係・語りの初期値は `scripts/demo/seed-shared-family-demo.sql` を基準とする。①②の追加人物・関係・語りは、対象家族に属することを確認してから削除し、②の3問を基準値へ戻す。③の制作中回答は基準の架空本文へ戻し、追加した音声・写真がある場合は既存のメディア削除手順でStorageとDBの両方を扱う。DB行だけを消して実ファイルを残さない。

④の公開済みWebブックと固定スナップショットは上書き・削除しない。基準の完成作品を維持し、原本・プロフィールなど可変部分を戻す。もし完成版そのものを作り直す必要が出たら、新しいデモ作品として発行し、旧公開URLの扱いを個別に確認する。

復元後は①の空状態、②の3問、③の制作再開、④の本棚・Webブックを再確認し、4ユーザーだけを許可リストに戻す。実顧客や既存購入作品には触れない。
