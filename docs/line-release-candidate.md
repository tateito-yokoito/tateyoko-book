# LINE公開候補（2026-10-20）

このブランチは `origin/main` から作成し、LINE認証・通知UIとLINE専用のサーバー部品を切り出した。元の作業ツリーにある本・管理画面等の大量の別変更は含まない。

- `VITE_LINE_AUTH_ENABLED` の既定値は `false`。本番にはまだ公開しない。
- LINEのみの利用者はStripe Checkoutへ空のメールアドレスを渡さない。
- DBに有効な受け取り時間が保存されるまで、画面の「LINEで受け取る」を有効にしない。
- LINE/決済テスト26件、`npm run build`、単一アプリの公開エントリ検査は成功。
- LINEの接続、Webhook、送信ヘルパー、DB移行のソースを含む。移行はテスト/本番DBには既に適用済み。再適用しない。
- 配信workerのソースはこの候補では更新していない。既に配置済みのworkerを再デプロイしないこと。LINE以外も含むworker全体の取り込みは安全審査で拒否されたため、分割検証・明示確認なしに迂回しない。
- 実際の問いのLINE配信、LINEから外部ブラウザへの復帰、無料３問および既存メール/SMSの実機回帰、本番Auth接続は未完了。これらを確認してからフラグを有効化する。
- 2026-10-20: テスト環境で専用の仮プロジェクト・問い・配信予定を作り、送信待ちが対象1件だけであることを確認した。配置済み `super-task` を Vault の service-role 資格情報で呼んだところ HTTP 401（worker の認証拒否）となり、LINE通知は送られていない。worker の認証を緩めず、テスト用の仮データを削除し、利用者の LINE 通知と通知設定を元の OFF に戻した。再確認時、仮データ各0件・送信待ち0件。テスト環境の `LINE_DELIVERY_ENABLED` も OFF に復元済み。worker 実送信は別途、安全なサーバー間認証経路を用意して再検証する。
- 実機は現時点で iPhone のみ利用可能。Android の LINE→外部ブラウザは未検証のまま公開済みと扱わない。
