# 姿を残す動画の仕様

## 目的

音声を中心にした体験は変えず、顔、声、間、身ぶりまで残したい場面だけを動画にする。動画の本数を増やすことではなく、家族にとって象徴になる短い記録を残すことを目的とする。

## MVPで確定する範囲

- 動画は任意。使わなくても今までどおり本を完成できる。
- 一冊につき最大2本。
- 一本につき最大2分。
- 縦向き、720p、正面の一人撮影を基本にする。
- 日々届く質問は、これまでどおり音声で答える。
- 動画は質問画面へ常設せず、ホームの「姿を残す」から収録する。
- 動画のためにQRを増やさない。一冊につき一つのQRを維持する。

## 残す二つの場面

### 1. 好きな語りを、姿でも残す

録音済みの語りから本人が一つ選び、同じ記憶を短く動画で語る。全文を語り直す必要はない。

### 2. 本をひらく家族へ

本を受け取る人へ、今の言葉を直接残す。冊子の完成が近づいた時に案内する。

どちらか一つだけでもよく、後から二つ目を追加できる。完成前までは撮り直しと削除ができる。

## 収録の体験

1. ホームに「姿を残す　0/2」を表示する。
2. 二つの場面から選ぶ。
3. カメラとマイクの確認を一画面で行う。
4. 顔の位置を示す薄い枠と、明るさの簡単な案内を表示する。
5. 大きな録画ボタンを押すと3秒後に開始する。
6. 残り時間ではなく経過時間を小さく表示する。
7. 停止後に再生し、「残す」「撮り直す」を選ぶ。
8. 「残す」を選んだ後、途中で切れても再開できる方法でアップロードする。

収録中は文章を読ませない。画面には録画状態、停止、カメラ切替だけを残す。

## 文字起こしと文章

- 動画にも文字起こしを作る。
- 動画ファイルをそのまま文章生成の入力にはしない。音声部分を文字起こしへ渡す。
- 先行体験では24MB以下のMP4を既存の文字起こしへ渡せるようにする。
- 正式版では動画から音声のみのファイルを自動生成し、文字起こしと低速回線向け再生に利用する。
- 冊子本文に採用するか、動画だけを残すかを選べる。

## デジタル冊子／Viewer

- 一覧では対象の声に小さな動画アイコンを付ける。
- 最初から動画を読み込まず、静止画と大きな再生ボタンだけを表示する。
- 利用者が押した時に、その動画一件だけの短時間URLを発行する。
- 自動再生はしない。
- 「動画を見る」と「音声だけ聴く」を選べる。
- 動画を見終わった後は、次の声へ進む操作を音声と共通にする。
- 冊子には動画の代表静止画と「動画あり」を入れられるが、QRは共通の一つを使う。

## 公開版と長期保存

- 元動画、再生用動画、音声版、代表静止画を別の素材として管理する。
- 本の公開時に、再生用動画、音声版、代表静止画を公開版へ固定する。
- 公開後に動画を黙って差し替えない。変更時は新しい版として扱う。
- 印刷後は同じQRを維持する。
- 動画だけが将来再生できなくなった場合にも、音声と文章は残る構成にする。

## プライバシー

- 収録前に、顔、部屋、周囲の音が残ることを短く知らせる。
- 本人以外が映る場合は、公開範囲を確認してから保存する。
- 動画を含む本では暗証番号の設定をおすすめするが、設定は任意とする。
- 公開前は本人または管理者が削除できる。
- 公開後の停止、削除、家族共有は音声版と同じルールにする。

## アクセス急増への対策

- ページを開いただけでは動画を配信しない。
- 動画URLの発行回数を、音声より低い基準で制限する。
- 一作品の動画URL発行が短時間または一日単位の基準を超えたら、その作品を自動停止する。
- URLは一件ずつ発行し、動画用は10分を目安に失効させる。
- 公開宣伝へ使う場合は、家族利用とは別の公開モードと配信基盤を用意する。

## 容量と費用の目安

720p、総ビットレート約1.2Mbps、2分を目安にすると、一本は約18MB、二本で約36MBになる。

| 単位 | 目安 |
| --- | ---: |
| 元動画2本 | 約36MB |
| 公開用の複製、音声版、静止画を含む一冊 | 約75MB |
| 1,000冊 | 約75GB |
| 二本とも最後まで再生を1,000回 | 約36GBの転送 |
| 二本とも最後まで再生を10,000回 | 約360GBの転送 |

通常の家族利用では保存費よりも、動画が外部公開されて大量再生された時の転送量が大きな変動要因になる。

## 技術面への影響

### 追加が必要なもの

- カメラ権限、録画、撮り直しのUI
- 6MB単位の再開可能アップロード
- 動画の形式確認と端末ごとの対応判定
- 代表静止画の生成
- 音声版の生成
- 公開版への複製
- Viewerの動画再生と音声だけの再生
- 動画専用のアクセス上限

### 難所

- iPhoneとAndroidで録画形式が異なる可能性がある。
- 大きなファイルは回線切断と画面終了の影響を受けやすい。
- 正式版では再生形式を揃える処理が必要になる。
- Supabase Edge Functionだけで動画変換を完結させず、動画処理用の実行基盤を分ける必要がある。

## 段階的な実装

### 先行体験

- 対応端末をiPhone Safariと主要Android Chromeに限定して実機検証する。
- 最大2本、各2分、24MB以下を基本にする。
- 対応形式を端末上で確認し、対応できない場合は音声収録へ戻す。
- 既存の非公開Storage、公開版、Viewerの仕組みに追加する。

### 正式リリース前

- 動画を標準形式に揃える処理を追加する。
- 音声版と代表静止画を自動生成する。
- 動画の転送量と自動停止を管理画面で確認できるようにする。
- 大量公開の要望が出た時だけ、動画配信基盤の分離を検討する。
